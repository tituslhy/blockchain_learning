Section 1 / 6

The Big Picture

Forget "it's decentralized" — that word alone explains nothing. Start with the actual problem blockchain solves, and the mechanism makes sense on its own.

Your own first answer, corrected

The very first working definition landed almost right: a blockchain is like a historical timeline, where each block is an event, time only flows forward, and you can't rewrite what already happened.

blockchain is like a historical timeline where each block is a historical event. time only flows forward, not backward, so you cannot undo the creation of a block.Working definition, before any code existed

Close, but one word needed sharpening: it's not that undoing history is impossible — it's that it's economically and computationally suicidal. Immutability isn't a law of physics here, it's a very expensive lock. This is called probabilistic finality, and it's the entire premise behind a "51% attack" (Section 3): someone paying the insane cost to rewrite history anyway.

Key Insight

Transparency ("anyone can see it") and decentralization ("no single party owns it") are two independent properties, not one bundled feature. Bitcoin has both. Mastercard's own blockchain work (Section 4) deliberately has decentralization — several banks jointly run it — without public transparency. Knowing which axis you're actually talking about matters.

Two independent dials, not one switch. "Decentralized" tells you nothing about who can see it, and "transparent" tells you nothing about who controls it.

The actual reason consensus exists: double-spend

Here's the derivation that matters more than any definition: if there's no central referee, what stops someone with $100 from broadcasting two valid, correctly-signed spends of that same $100 at once — to two different people, at the same instant?

if you have only $100 left and two blocks of a $100 spend are written at the same time you get a race condition. and a physical singularity - it's impossible to double spend the same $100 unless it's a buy one get one freeDeriving the double-spend problem, unprompted

That's the double-spend problem in full, arrived at from first principles: both transactions are individually, cryptographically valid. The problem was never fraud detection — it's that there's no natural way to know which one happened "first" when nobody runs a shared clock and nobody's in charge.

The Double-Spend Problem

Alice only has $100. She just told two people she'd send it. One of them is about to have a very bad day, and nobody has decided which one yet.

The Byzantine Generals Problem

Double-spend is the currency-flavored version of a much older, more general problem: how do a bunch of computers, run by strangers, some possibly lying, agree on a single shared truth with no boss, no HQ, and no way to verify who's trustworthy? Several generals surround a city. They must all attack together or all retreat together — a split decision loses. They can only communicate via messengers who might be captured, and some generals might be traitors sending deliberately conflicting orders. How do the loyal ones still coordinate?

Byzantine Generals Problem

Nobody knows who to trust, the messengers might be intercepted, and General C is giving off serious energy. Attack anyway and hope for the best, or retreat and hope everyone else also retreated?

Cross-Reference

This is mechanism design wearing a distributed-systems costume — designing a game where honest behaviour is the dominant strategy even assuming some players are adversarial. Direct cross-reference to Game Theory 101. Proof of Work (Section 3) is one answer: make lying prohibitively expensive in electricity. Proof of Stake is a different answer: make lying prohibitively expensive in your own staked capital instead.

What a "block" actually is

A block is just a labelled box. What goes inside is entirely up to whoever's using the chain — Bitcoin puts transactions in it, Ethereum puts transactions and smart-contract instructions, and OpenCerts (Section 4) puts a single hash representing an entire batch of diplomas. The blockchain itself only guarantees one thing: whatever you put in the box becomes permanent and tamper-evident. It is, delightfully, the least mysterious part of this entire field — everyone talks about "the blockchain" like it's a glowing cube from a heist movie, and it's a box. It's a labelled cardboard box that remembers what was in it.

Key Takeaway
Blockchain exists to solve one problem: getting mutually distrusting strangers to agree on a single shared history, with no referee. Everything from here — hashing, mining, staking, permissioned networks — is just a different engineering answer to that exact question.

Anatomy of a Block

Two properties do all the work here: hashing is deterministic (same input, same output, always) and it's a genuine one-way street — you cannot work backwards from an output to find an input. Everything below is built on those two facts.

V1 — a chain of blocks, and what tampering actually looks like

The minimal version: each block stores its own data, the hash of the block before it, and its own hash — computed, never assigned. is_valid() just re-derives every hash fresh and checks it against what's stored.

"""
Blockchain 101 -- Toy Example #1: The Anatomy of a Block
A minimal, dependency-free blockchain to show ONE thing clearly:
each block contains the hash of the block before it, so tampering
with ANY block breaks the hash of every block after it.

No mining yet. No consensus yet. Just the "chain" part of "blockchain."
"""

import hashlib
import json
import time


class Block:
    def __init__(self, index, data, previous_hash):
        self.index = index
        self.timestamp = time.time()
        self.data = data
        self.previous_hash = previous_hash
        self.hash = self.compute_hash()

    def compute_hash(self):
        # Turn this block's contents into one deterministic string...
        block_contents = json.dumps({
            "index": self.index,
            "timestamp": self.timestamp,
            "data": self.data,
            "previous_hash": self.previous_hash,
        }, sort_keys=True)
        # ...then hash it. Same input -> same output. Always. Everywhere.
        return hashlib.sha256(block_contents.encode()).hexdigest()

    def __repr__(self):
        return (f"Block #{self.index}\n"
                f"  data:          {self.data}\n"
                f"  previous_hash: {self.previous_hash[:16]}...\n"
                f"  hash:          {self.hash[:16]}...\n")


class Blockchain:
    def __init__(self):
        # every chain needs a first block with no parent -- the "genesis block"
        self.chain = [Block(0, "Genesis Block", "0" * 64)]

    def add_block(self, data):
        previous_block = self.chain[-1]
        new_block = Block(len(self.chain), data, previous_block.hash)
        self.chain.append(new_block)

    def is_valid(self):
        for i in range(1, len(self.chain)):
            current = self.chain[i]
            previous = self.chain[i - 1]

            # Rule 1: this block's stored hash must match what we get
            # from recomputing it right now.
            if current.hash != current.compute_hash():
                return False, f"Block #{current.index} was tampered with directly."

            # Rule 2: this block must correctly point to the block before it.
            if current.previous_hash != previous.hash:
                return False, f"Block #{current.index} is disconnected from Block #{previous.index}."

        return True, "Chain is valid."

    def print_chain(self):
        for block in self.chain:
            print(block)


if __name__ == "__main__":
    print("=== Building the chain ===\n")
    titus_chain = Blockchain()
    titus_chain.add_block("Titus joins Mastercard R&D, 6 July 2026")
    titus_chain.add_block("Titus starts NTU MSc in Blockchain")
    titus_chain.add_block("Titus finally understands why PoW isn't magic")

    titus_chain.print_chain()

    valid, msg = titus_chain.is_valid()
    print(f"Chain valid? {valid} -- {msg}\n")

    print("=== Attempt 1: sloppy tamper -- edit the data, leave the old hash ===\n")
    titus_chain.chain[1].data = "Titus joins Mastercard R&D... as a spy for a rival bank"

    valid, msg = titus_chain.is_valid()
    print(f"Chain valid? {valid} -- {msg}\n")

    print("=== Attempt 2: clever tamper -- also recompute Block #1's own hash to cover tracks ===\n")
    titus_chain.chain[1].hash = titus_chain.chain[1].compute_hash()

    valid, msg = titus_chain.is_valid()
    print(f"Chain valid? {valid} -- {msg}")

Tamper with Block 1 and its hash changes — but Block 2 already memorized the OLD hash. Forge Block 2 to match, and Block 3 catches THAT. The chain doesn't need a guard dog. It just remembers.

Editing a block's data without re-hashing gets caught instantly. Even re-hashing to "cover your tracks" gets caught one block later — the next block already carries a permanent memory of what your hash used to be. Tampering with block N in a chain of length L means re-forging every block from N to L. On a four-block toy chain that's three re-forgeries. On real Bitcoin, tampering with a 2019 transaction means re-mining every block since 2019, faster than the entire planet's miners combined. That's not a metaphorical wall.

The Merkle tree: proving one thing without revealing everything else

Real batches don't get concatenated into one flat blob and hashed — that would mean anyone verifying a single document needs every other document in the batch too, which is both wasteful and a genuine privacy disaster. Instead, think of it as a knockout tournament: pair documents up, hash each pair together, pair up the winners, hash again, repeat until exactly one hash remains — the Merkle root.

Analogy

To prove your diploma was in the tournament, you only need the specific opponents your diploma "faced" on the way to the final — not the whole bracket. For 8 diplomas that's 3 hashes, not 7. For 10,000 diplomas it's about 14 hashes (log₂ of 10,000), not 9,999.

8 Diplomas → 1 Root

Titus (T, leaf 3) needs exactly the highlighted path: P1, G0, and the root. Alice, Bob, Emma, Farid, Grace, and Hafiz never have to hand over so much as a hall pass.

"""
Blockchain 101 -- Toy Example #7: Merkle Trees.

How NUS publishes ONE hash for a whole batch of diplomas, while any one
graduate can prove their specific diploma was in that batch -- without
needing, revealing, or even seeing anyone else's diploma.
"""

from __future__ import annotations

import hashlib


def sha256(data: str) -> str:
    """Deterministic hash helper used throughout."""
    return hashlib.sha256(data.encode()).hexdigest()


class MerkleTree:
    """A binary tree of hashes, built bottom-up from a list of documents.

    Each document becomes a "leaf" (individually hashed). Leaves are
    paired up and hashed together to form the next layer up. This
    repeats until exactly one hash remains -- the "Merkle root" -- which
    is the ONLY thing that needs to be published on-chain.

    Attributes:
        leaves: Hashes of the original documents, in order.
        layers: Every layer of the tree, from leaves (layers[0]) up to
            the root (layers[-1], containing exactly one hash).
    """

    def __init__(self, documents: list[str]) -> None:
        if not documents:
            raise ValueError("Need at least one document to build a tree.")
        self.leaves: list[str] = [sha256(doc) for doc in documents]
        self.layers: list[list[str]] = [self.leaves]
        self._build()

    def _build(self) -> None:
        """Repeatedly hash pairs of the current layer until one hash remains."""
        current = self.layers[0]
        while len(current) > 1:
            next_layer: list[str] = []
            for i in range(0, len(current), 2):
                left = current[i]
                # odd count -> duplicate the last item so it can pair with itself
                right = current[i + 1] if i + 1 < len(current) else current[i]
                next_layer.append(sha256(left + right))
            self.layers.append(next_layer)
            current = next_layer

    @property
    def root(self) -> str:
        """The single hash summarizing the ENTIRE batch of documents."""
        return self.layers[-1][0]

    def get_proof(self, leaf_index: int) -> list[tuple[str, str]]:
        r"""Build the minimal sibling-hash path proving a document's membership.

        This is the entire point of the structure: instead of needing
        ALL other documents, you need exactly one sibling hash per
        LEVEL of the tree -- log2(N) hashes total, not N-1.

        WORKED EXAMPLE (this is the exact tree our 8 diplomas build):

            Layer 0 (leaves):   L0   L1   L2   L3   L4   L5   L6   L7
                                  \  /       \  /      \  /      \  /
            Layer 1:               P0         P1         P2        P3
                                      \        /            \       /
            Layer 2:                    G0                     G1
                                           \                   /
            Layer 3 (root):                      ROOT

            where P0=hash(L0,L1), P1=hash(L2,L3), P2=hash(L4,L5),
                  P3=hash(L6,L7), G0=hash(P0,P1), G1=hash(P2,P3),
                  ROOT=hash(G0,G1).

            Titus's diploma is L3 (leaf_index=3). His path UP the tree is
            L3 -> P1 -> G0 -> ROOT. To rebuild that path himself, at each
            step he needs whichever hash he's missing to complete the pair:

              Step 1 (layer 0, index=3):
                3 is ODD -> L3 is the RIGHT child of the pair (L2, L3).
                Missing piece: L2 (index 2). Combine as hash(L2 + L3).
                -> proof records ("left", L2)   [sibling goes on the left]
                -> new index for next layer: 3 // 2 = 1

              Step 2 (layer 1, index=1):
                1 is ODD -> P1 is the RIGHT child of the pair (P0, P1).
                Missing piece: P0 (index 0). Combine as hash(P0 + P1).
                -> proof records ("left", P0)
                -> new index: 1 // 2 = 0

              Step 3 (layer 2, index=0):
                0 is EVEN -> G0 is the LEFT child of the pair (G0, G1).
                Missing piece: G1 (index 1). Combine as hash(G0 + G1).
                -> proof records ("right", G1)   [sibling goes on the right]
                -> new index: 0 // 2 = 0, loop ends (root layer reached)

            Final proof = [("left", L2), ("left", P0), ("right", G1)] --
            exactly 3 hashes, matching the live output. verify_proof()
            then just replays these three combinations in order, starting
            from Titus's own leaf hash, and checks it lands on ROOT.

        Args:
            leaf_index: Position of the document to prove membership for.

        Returns:
            A list of (position, hash) pairs. Position ("left"/"right")
            tells the verifier which side of the combination the
            sibling hash belongs on.
        """
        proof: list[tuple[str, str]] = []
        index = leaf_index
        for layer in self.layers[:-1]:  # every layer except the root itself
            is_right_node = index % 2 == 1
            pair_index = index - 1 if is_right_node else index + 1
            if pair_index < len(layer):
                sibling_hash = layer[pair_index]
                position = "left" if is_right_node else "right"
                proof.append((position, sibling_hash))
            index //= 2
        return proof


def verify_proof(leaf_hash: str, proof: list[tuple[str, str]], root: str) -> bool:
    """Independently recompute the root from a leaf hash + its proof, and
    check it matches the published root -- without ever seeing any other
    document in the batch.

    Args:
        leaf_hash: Hash of the document being proven.
        proof: Sibling hashes returned by MerkleTree.get_proof().
        root: The published root hash to check against.

    Returns:
        True if the leaf genuinely belongs to the tree that produced root.
    """
    current_hash = leaf_hash
    for position, sibling_hash in proof:
        if position == "left":
            current_hash = sha256(sibling_hash + current_hash)
        else:
            current_hash = sha256(current_hash + sibling_hash)
    return current_hash == root

OpenCerts, for real

This isn't hypothetical — it's exactly how Singapore's own OpenCerts works. Built by GovTech, SkillsFuture SG, MOE, and Ngee Ann Poly, on public Ethereum. Your actual diploma — name, grades, institution — never touches the blockchain. Only a hash does. NUS issues your diploma, hashes it, publishes the batch's Merkle root, and you keep the actual file plus your own proof, embedded permanently. An employer re-hashes your file and checks it against the on-chain root. That same trick got spun off into TradeTrust, doing the identical thing for bills of lading in international shipping. Somewhere, a shipping container full of iron ore is more cryptographically verifiable than most people's LinkedIn "Experience" section.

The full lifecycle: build once, hand out proofs, discard the tree

The tree only needs to exist for one moment — issuance, the only time all documents exist together in one place. After that, each graduate personally carries their own tiny slice of the proof, permanently, inside their own file. Nobody needs "the tree" ever again.

"""
Blockchain 101 -- Toy Example #8: The full Merkle certificate lifecycle.

Demonstrates that the full tree is needed EXACTLY ONCE -- at issuance --
and can be discarded immediately after. Verification, years later, uses
only (a) the graduate's own certificate and (b) the root looked up
on-chain. No tree object exists anywhere by that point.

@dataclass
class Certificate:
    """What a graduate actually receives and keeps -- self-contained and
    independently verifiable forever. No tree required, ever again.

    Attributes:
        holder: Whose certificate this is.
        content: The actual diploma text (what gets hashed as the leaf).
        proof: This holder's personal sibling-hash path to the root,
            computed once at issuance time and embedded here permanently.
    """
    holder: str
    content: str
    proof: list[tuple[str, str]]


def issue_batch(holders: list[str], contents: list[str]) -> tuple[dict[str, Certificate], str]:
    """NUS's one-time issuance process.

    This function is the ONLY place in the entire system where the full
    Merkle tree ever exists. It's built, used to generate every
    graduate's individual proof, and then goes out of scope the moment
    this function returns -- nothing outside keeps a reference to it.

    Args:
        holders: Names of the graduates in this batch.
        contents: The diploma text for each graduate, same order.

    Returns:
        (certificates keyed by holder name, the Merkle root to publish on-chain)
    """
    tree = MerkleTree(contents)
    root = tree.root

    certificates: dict[str, Certificate] = {}
    for i, (holder, content) in enumerate(zip(holders, contents)):
        proof = tree.get_proof(i)
        certificates[holder] = Certificate(holder=holder, content=content, proof=proof)

    return certificates, root
    # <- `tree` dies here. Python garbage-collects it. It is never coming back.


def verify_certificate(cert: Certificate, published_root: str) -> bool:
    """Standalone verification: only this certificate + an on-chain root.

    No tree object exists anywhere at the point this function runs --
    none is constructed, none is needed.

    Args:
        cert: The certificate being checked.
        published_root: The root looked up from the blockchain.

    Returns:
        True if this certificate genuinely belongs to the batch that
        produced published_root.
    """
    leaf_hash = sha256(cert.content)
    return verify_proof(leaf_hash, cert.proof, published_root)

Consensus Mechanisms, Properly

Two completely different engineering answers to the same Byzantine Generals question: how do you make lying prohibitively expensive?

Proof of Work: an expensive lottery

Mining and verifying are not the same operation. Mining is probabilistic brute force — guess a number (the nonce), hash the block, check if the result starts with enough zeros, repeat millions of times. Verifying is instant and deterministic — the same hash function that took millions of guesses to satisfy takes exactly one calculation to check.

Analogy

Solving a hard Sudoku might take twenty minutes of genuine effort. Checking a completed Sudoku takes ten seconds — just scan every row, column, and box. That asymmetry, hard to solve but trivial to check, is exactly the shape of Proof of Work, and it's why one exhausted miner can be checked for free by ten thousand bored verifiers.

import hashlib
import json
import time


class Block:
    def __init__(self, index, data, previous_hash, difficulty=5):
        self.index = index
        self.timestamp = time.time()
        self.data = data
        self.previous_hash = previous_hash
        self.difficulty = difficulty   # how many leading zeros the hash must have
        self.nonce = 0                 # the number we brute-force search over
        self.hash = self.mine()

    def compute_hash(self):
        block_contents = json.dumps({
            "index": self.index,
            "timestamp": self.timestamp,
            "data": self.data,
            "previous_hash": self.previous_hash,
            "nonce": self.nonce,          # nonce is now part of what gets hashed
        }, sort_keys=True)
        return hashlib.sha256(block_contents.encode()).hexdigest()

    def mine(self):
        target = "0" * self.difficulty
        start = time.time()
        attempts = 0
        candidate_hash = self.compute_hash()
        while not candidate_hash.startswith(target):
            self.nonce += 1
            attempts += 1
            candidate_hash = self.compute_hash()
        elapsed = time.time() - start
        print(f"  mined Block #{self.index} in {attempts:,} attempts, {elapsed:.2f}s "
              f"(nonce={self.nonce}, hash={candidate_hash[:16]}...)")
        return candidate_hash

    def __repr__(self):
        return (f"Block #{self.index}\n"
                f"  data:          {self.data}\n"
                f"  nonce:         {self.nonce}\n"
                f"  previous_hash: {self.previous_hash[:16]}...\n"
                f"  hash:          {self.hash[:16]}...\n")

Bullshit Detector

You cannot "cheat" by editing a hash's output directly — a hash isn't a field you fill in, it's a consequence that falls out the instant you commit to an input. This is preimage resistance: SHA-256 is deliberately built so the backward direction (output → input) is computationally infeasible, not just inconvenient. Combined with the avalanche effect — change the input by one character and the output scrambles unpredictably — there is no partial credit, no "getting warmer." Only brute force works, on purpose.

Proof of Stake: expensive collateral instead of expensive electricity

No mining loop. Instead: lock up real capital as a stake, get selected to propose the next block via a weighted lottery (more stake, better odds, never guaranteed), and if you're caught cheating, the protocol algorithmically destroys your deposit. Landlord-deposit energy instead of marathon-runner energy.

Reality Bite

The real bug we found and fixed. An early version checked a validator's eligibility using their current slashed status — which meant a validator's later crime retroactively invalidated their perfectly honest earlier blocks. The fix: give each validator a slashed_at_height marker instead of a plain True/False switch, so eligibility is judged as of the height in question, not against a live, constantly-changing status. Block 5 stays valid even after the same validator gets caught cheating at block 6. History that was honest when it happened should stay honest.

Key Insight

Proposer selection uses secrets.randbelow(), not Python's ordinary random module — a catch that came from a SonarQube warning during this build, not a lecture. random is a Mersenne Twister: deterministic and predictable once its state is known. Predictable proposer selection is a real attack vector — an attacker could pre-target whoever's about to be picked, or bias selection ("grinding"). Real chains take this seriously: Ethereum combines RANDAO with a VDF, Algorand uses a Verifiable Random Function. Same underlying requirement, independently rediscovered.

"""
Blockchain 101 -- Toy Example #6: Rewards, compounding, and accidental
equivocation.

Builds on v5 (Validator, Block, Blockchain, pick_proposer, slash are
unchanged in spirit -- see that file for full annotation). Two additions:

  1. Reward mechanics -- proposers earn a block reward + transaction fees,
     credited directly to their stake. Run enough rounds and you can watch
     the "rich get richer" dynamic happen numerically, not just in theory.

  2. Accidental equivocation -- a well-intentioned redundancy setup (the
     SAME validator identity running "primary" and "backup" processes for
     reliability) accidentally produces two conflicting signatures during
     a botched failover. detect_equivocation() cannot tell this apart from
     deliberate cheating -- and in the real world, neither can Ethereum.
     This is why "just run a backup machine" is a genuine anti-pattern in
     PoS systems, unlike almost every other kind of distributed system.
"""

from __future__ import annotations

import hashlib
import json
import secrets
import time
from typing import Optional

BLOCK_REWARD: float = 2.0    # newly issued currency paid to the proposer
FEE_PER_TX: float = 0.1      # fee paid by each transaction bundled into the block


class Validator:
    """A network participant who has locked up a stake as collateral.

    Attributes:
        name: Human-readable identifier for this validator.
        stake: Currency locked up. Grows over time as rewards/fees are
            earned -- see Blockchain.add_block().
        slashed_at_height: Block height at which this validator was
            caught cheating, or None if never slashed.
    """

    def __init__(self, name: str, stake: float) -> None:
        self.name = name
        self.stake = stake
        self.slashed_at_height: Optional[int] = None

    @property
    def is_slashed(self) -> bool:
        """Whether this validator has ever been slashed, at any point."""
        return self.slashed_at_height is not None

    def was_eligible_at(self, height: int) -> bool:
        """Was this validator in good standing as of the given height?"""
        if self.slashed_at_height is None:
            return True
        return height < self.slashed_at_height

    def __repr__(self) -> str:
        status = f"SLASHED at height {self.slashed_at_height}" if self.is_slashed else "active"
        return f"{self.name}: stake={self.stake:.2f} [{status}]"


class Block:
    """A single entry in the chain.

    Attributes:
        index: Position in the chain (0 = genesis).
        data: The payload for this block.
        previous_hash: Hash of the block immediately before this one.
        proposer: Name of the validator who proposed this block.
        num_transactions: How many transactions this block bundles --
            used to calculate the proposer's fee earnings.
        hash: This block's own hash, computed once at creation.
    """

    def __init__(
        self,
        index: int,
        data: str,
        previous_hash: str,
        proposer: str,
        num_transactions: int = 1,
    ) -> None:
        self.index = index
        self.timestamp = time.time()
        self.data = data
        self.previous_hash = previous_hash
        self.proposer = proposer
        self.num_transactions = num_transactions
        self.hash = self.compute_hash()

    def compute_hash(self) -> str:
        """Deterministically hash this block's contents."""
        block_contents = json.dumps(
            {
                "index": self.index,
                "timestamp": self.timestamp,
                "data": self.data,
                "previous_hash": self.previous_hash,
                "proposer": self.proposer,
                "num_transactions": self.num_transactions,
            },
            sort_keys=True,
        )
        return hashlib.sha256(block_contents.encode()).hexdigest()

    def __repr__(self) -> str:
        return (
            f"Block #{self.index} proposed by {self.proposer} "
            f"({self.num_transactions} txs)\n"
            f"  data: {self.data}\n"
        )


def pick_proposer(validators: list[Validator]) -> Validator:
    """Select the next proposer at random, weighted by stake, using a
    cryptographically secure random source (see v4/v5 for full rationale
    on why `secrets` and not `random`)."""
    active = [v for v in validators if not v.is_slashed]
    weights = [v.stake for v in active]
    total = sum(weights)
    pick = secrets.randbelow(int(total * 1000)) / 1000  # sub-integer precision, stakes now have decimals
    cumulative = 0.0
    for validator, weight in zip(active, weights):
        cumulative += weight
        if pick < cumulative:
            return validator
    return active[-1]


def slash(validator: Validator, height: int, penalty_fraction: float = 1.0) -> None:
    """Destroy a fraction of a validator's stake and record when it happened.

    Args:
        validator: The validator being punished.
        height: Block height at which the misbehaviour occurred.
        penalty_fraction: Fraction of stake destroyed (0 to 1). Real
            protocols vary this by severity -- a small accidental
            first offence is penalized far more gently than repeated
            or coordinated attacks.
    """
    lost = validator.stake * penalty_fraction
    validator.stake -= lost
    validator.slashed_at_height = height
    print(
        f"  SLASHED: {validator.name} loses {lost:.2f} coins "
        f"({penalty_fraction:.0%} of stake) at height {height}. "
        f"Remaining stake: {validator.stake:.2f}"
    )


class Blockchain:
    """Owns the chain; enforces legitimacy rules for new blocks."""

    def __init__(self, validators: list[Validator]) -> None:
        self.validators = validators
        self.chain: list[Block] = [Block(0, "Genesis Block", "0" * 64, "network")]

    def add_block(self, data: str, num_transactions: int = 1) -> tuple[Block, Validator]:
        """Select a proposer, append their block, and pay them.

        The proposer earns BLOCK_REWARD (newly issued currency) plus
        num_transactions * FEE_PER_TX (fees from whoever's transactions
        got bundled in), credited straight into their stake. Since stake
        determines future selection odds, this is the entire "rich get
        richer" mechanic in three lines.

        Args:
            data: The payload for the new block.
            num_transactions: How many transactions this block bundles.

        Returns:
            (the new Block, the Validator who proposed and earned from it)
        """
        proposer = pick_proposer(self.validators)
        previous_block = self.chain[-1]
        new_block = Block(
            len(self.chain), data, previous_block.hash, proposer.name, num_transactions
        )
        self.chain.append(new_block)

        earnings = BLOCK_REWARD + num_transactions * FEE_PER_TX
        proposer.stake += earnings

        return new_block, proposer

    def is_valid(self) -> tuple[bool, str]:
        """Re-verify the whole chain: tamper-evidence, linkage, and
        proposer eligibility judged AS OF each block's own height."""
        validators_by_name = {v.name: v for v in self.validators}
        for i in range(1, len(self.chain)):
            current, previous = self.chain[i], self.chain[i - 1]
            if current.hash != current.compute_hash():
                return False, f"Block #{current.index} was tampered with directly."
            if current.previous_hash != previous.hash:
                return False, f"Block #{current.index} is disconnected from Block #{previous.index}."
            proposer = validators_by_name.get(current.proposer)
            if proposer is None:
                return False, f"Block #{current.index} was proposed by an unknown validator."
            if not proposer.was_eligible_at(current.index):
                return False, (
                    f"Block #{current.index} was proposed by {proposer.name}, who was "
                    f"already slashed (at height {proposer.slashed_at_height}) by then."
                )
        return True, "Chain is valid."

    def detect_equivocation(
        self, index: int, proposer_name: str, candidate_blocks: list[Block]
    ) -> tuple[bool, str]:
        """Detect a proposer signing multiple conflicting blocks for the
        same height. NOTE: this function has zero concept of intent --
        it purely compares hashes. That's not a simplification; that's
        exactly how real protocols work. They cannot read minds."""
        hashes = {b.hash for b in candidate_blocks}
        if len(hashes) > 1:
            return True, (
                f"{proposer_name} signed {len(hashes)} conflicting blocks "
                f"at height {index} -- equivocation."
            )
        return False, "No equivocation detected."

# Shared hashing primitive

def sha256(data: str) -> str:
    """Deterministic hash helper used by every layer below."""
    return hashlib.sha256(data.encode()).hexdigest()


# ---------------------------------------------------------------------------
# Layer 1: Merkle trees -- batching many documents into one provable root
# ---------------------------------------------------------------------------

class MerkleTree:
    """A binary tree of hashes built bottom-up from a list of documents.
    See toy_blockchain_v7 for the fully worked index-arithmetic example."""

    def __init__(self, documents: list[str]) -> None:
        if not documents:
            raise ValueError("Need at least one document to build a tree.")
        self.leaves: list[str] = [sha256(doc) for doc in documents]
        self.layers: list[list[str]] = [self.leaves]
        self._build()

    def _build(self) -> None:
        current = self.layers[0]
        while len(current) > 1:
            next_layer: list[str] = []
            for i in range(0, len(current), 2):
                left = current[i]
                right = current[i + 1] if i + 1 < len(current) else current[i]
                next_layer.append(sha256(left + right))
            self.layers.append(next_layer)
            current = next_layer

    @property
    def root(self) -> str:
        """The single hash summarizing the entire batch -- this, and only
        this, is what ends up inside a Block's data field below."""
        return self.layers[-1][0]

    def get_proof(self, leaf_index: int) -> list[tuple[str, str]]:
        proof: list[tuple[str, str]] = []
        index = leaf_index
        for layer in self.layers[:-1]:
            is_right_node = index % 2 == 1
            pair_index = index - 1 if is_right_node else index + 1
            if pair_index < len(layer):
                sibling_hash = layer[pair_index]
                position = "left" if is_right_node else "right"
                proof.append((position, sibling_hash))
            index //= 2
        return proof


def verify_proof(leaf_hash: str, proof: list[tuple[str, str]], root: str) -> bool:
    """Recompute the root from a leaf + its proof. No tree object involved."""
    current_hash = leaf_hash
    for position, sibling_hash in proof:
        if position == "left":
            current_hash = sha256(sibling_hash + current_hash)
        else:
            current_hash = sha256(current_hash + sibling_hash)
    return current_hash == root

def issue_batch(holders: list[str], contents: list[str]) -> tuple[dict[str, Certificate], str]:

class Validator:

def pick_proposer(validators: list[Validator]) -> Validator:
    """Cryptographically secure, stake-weighted proposer selection.
    See toy_blockchain_v5/v6 for the full rationale on secrets vs random."""
    active = [v for v in validators if not v.is_slashed]
    weights = [v.stake for v in active]
    total = sum(weights)
    pick = secrets.randbelow(int(total * 1000)) / 1000
    cumulative = 0.0
    for validator, weight in zip(active, weights):
        cumulative += weight
        if pick < cumulative:
            return validator
    return active[-1]


def slash(validator: Validator, height: int, penalty_fraction: float = 1.0) -> None:
    lost = validator.stake * penalty_fraction
    validator.stake -= lost
    validator.slashed_at_height = height
    print(f"  SLASHED: {validator.name} loses {lost:.2f} coins at height {height}.")


class Blockchain:
    """Owns the chain; PoS-flavoured legitimacy rules (see v5 for the
    historical-eligibility bug fix this already includes)."""

    def __init__(self, validators: list[Validator]) -> None:
        self.validators = validators
        self.chain: list[Block] = [Block(0, "Genesis Block", "0" * 64, "network")]

    def add_block(self, data: str, num_transactions: int = 1) -> tuple[Block, Validator]:
        proposer = pick_proposer(self.validators)
        previous_block = self.chain[-1]
        new_block = Block(len(self.chain), data, previous_block.hash, proposer.name, num_transactions)
        self.chain.append(new_block)
        proposer.stake += BLOCK_REWARD + num_transactions * FEE_PER_TX
        return new_block, proposer

    def is_valid(self) -> tuple[bool, str]:
        validators_by_name = {v.name: v for v in self.validators}
        for i in range(1, len(self.chain)):
            current, previous = self.chain[i], self.chain[i - 1]
            if current.hash != current.compute_hash():
                return False, f"Block #{current.index} was tampered with directly."
            if current.previous_hash != previous.hash:
                return False, f"Block #{current.index} is disconnected from Block #{previous.index}."
            proposer = validators_by_name.get(current.proposer)
            if proposer is None:
                return False, f"Block #{current.index} was proposed by an unknown validator."
            if not proposer.was_eligible_at(current.index):
                return False, f"Block #{current.index} was proposed by an already-slashed validator."
        return True, "Chain is valid."

Public vs Permissioned Chains

This is where the job actually lives. Everything above describes Bitcoin and Ethereum — open to anyone, no ID required. Regulated banks cannot use that directly, and the reason why is precise, not vague.

Where is "the blockchain," physically?

No master server, anywhere. A public chain is stored redundantly, in full, by thousands of independent, voluntary nodes — anyone with a computer and disk space. Nobody approves you; you download open-source software, sync from genesis, and independently re-verify every block yourself rather than trusting anyone's copy.

Reality Bite

Almost nobody actually runs a full node in practice. Most everyday apps quietly query a third party (Infura, Alchemy) instead — technically decentralized, practically re-centralized at the access layer for convenience. And full nodes genuinely do store the real underlying data, not just hashes: without the data there's nothing left to check a hash against. "Pruned" nodes are the middle ground — verify everything as it arrives, then discard old raw data and keep only headers — but SOME nodes have to keep the full archive, or the network could never bootstrap a new participant again.

What Mastercard is actually doing

Mastercard's Multi-Token Network (MTN) is real and active — built on Mastercard's own private blockchain, supporting tokenized bank deposits, stablecoins (FIUSD, PYUSD), and real-world assets like carbon credits and tokenized US Treasuries. Mastercard has been at this since 2015, filed 250+ blockchain patents, and funded 43 blockchain startups through an accelerator. A recent pilot demonstrated MTN, JPMorgan's Kinexys blockchain, Ripple, and public infrastructure coordinating together to redeem a tokenized Treasury fund across banks in near real-time — a private, permissioned chain, deliberately built to interoperate with other institutions' private chains AND with public infrastructure.

That whole cluster — known participants, confidential transactions, controllable reversal, accountable validators — is exactly what a permissioned blockchain is engineered to provide. Same underlying primitives (hashing, chaining, consensus), with an explicit membership list bolted on at every layer.

Chaincode: smart contracts for known participants

A smart contract is just a deterministic program that every node independently re-runs and must agree on — the same "recompute it yourself" principle as is_valid(), applied to business logic instead of a hash check. Hyperledger Fabric's version, "chaincode," runs on a completely different architecture from Ethereum's "everyone re-executes everything": Execute-Order-Validate.

  1. Execute — specific, named, known "endorsing peers" run the chaincode locally and sign a result, without touching the shared ledger yet
  2. Order — a separate ordering service sequences already-endorsed transactions (Raft among known consortium members, not a lottery)
  3. Validate — before committing, every peer checks the endorsement policy was satisfied AND that nobody's state went stale underneath them

def transfer_chaincode(
    state: dict[str, float], frm: str, to: str, amount: float
) -> dict[str, float]:
    """A toy smart contract: deterministic, same result on every peer."""
    new_state = dict(state)
    if new_state.get(frm, 0) < amount:
        raise ValueError(f"Insufficient funds: {frm} has {new_state.get(frm, 0)}, needs {amount}")

    new_state[to] = new_state.get(to, 0) + amount

class PermissionedBlockchain:
    """The full picture: Execute-Order-Validate feeding INTO a real,
    hash-linked chain, plus a fast-lookup world_state snapshot derived
    from replaying it.

    Attributes:
        chain: The actual append-only, hash-linked history -- same
            tamper-evidence guarantees as every Block chain since v1.
        world_state: Current account balances, updated only when a
            transaction is successfully committed. This is a CACHE of
            "chain, replayed to the present" -- not a separate source
            of truth.
    """

    def __init__(
        self, required_endorsers: set[str], min_endorsements: int, orderer_name: str
    ) -> None:
        self.required_endorsers = required_endorsers
        self.min_endorsements = min_endorsements
        self.orderer_name = orderer_name
        self.chain: list[Block] = [Block(0, "Genesis Block", "0" * 64, orderer_name)]
        self.world_state: dict[str, float] = {}

    def submit(
        self, description: str, endorsements: list[Endorsement], final_state: dict[str, float]
    ) -> bool:
        """VALIDATE step, THEN wrap into a real Block if it passes.

        Args:
            description: Human-readable label for this transaction.
            endorsements: Signed results from the peers who ran it.
            final_state: The resulting world state, if accepted.

        Returns:
            True if committed as a new Block, False if rejected.
        """
        endorser_names = {e.peer_name for e in endorsements}

        if not endorser_names.issuperset(self.required_endorsers):
            missing = self.required_endorsers - endorser_names
            print(f"  REJECTED: missing required endorsers {missing}")
            return False

        if len(endorsements) < self.min_endorsements:
            print(f"  REJECTED: only {len(endorsements)} endorsements, need {self.min_endorsements}")
            return False

        result_hashes = {e.result_hash for e in endorsements}
        if len(result_hashes) > 1:
            print(f"  REJECTED: endorsers disagree -- {len(result_hashes)} different outcomes!")
            return False

        # Only NOW, after the policy is satisfied, does this become an
        # actual hash-linked Block -- same append mechanic as v1-v9.
        record = json.dumps(
            {"description": description, "resulting_state": final_state}, sort_keys=True
        )
        previous_block = self.chain[-1]
        new_block = Block(len(self.chain), record, previous_block.hash, self.orderer_name)
        self.chain.append(new_block)
        self.world_state = final_state

        print(f"  COMMITTED as Block #{new_block.index}: {description} "
              f"(endorsed by {sorted(endorser_names)})")
        return True

    def is_valid(self) -> tuple[bool, str]:
        """Re-verify the chain's tamper-evidence -- identical in spirit
        to every is_valid() since v1. Note what's DIFFERENT from PoW/PoS:
        there's no difficulty target and no proposer-eligibility check,
        because legitimacy was already fully enforced by the endorsement
        policy at submit() time, before a Block ever got created. Here,
        is_valid() only needs to catch POST-HOC tampering."""
        for i in range(1, len(self.chain)):
            current, previous = self.chain[i], self.chain[i - 1]
            if current.hash != current.compute_hash():
                return False, f"Block #{current.index} was tampered with directly."
            if current.previous_hash != previous.hash:
                return False, f"Block #{current.index} is disconnected from Block #{previous.index}."
        return True, "Chain is valid."

Endorsement happens before a transaction's turn to commit.     """What chaincode execution actually produces: not just a new value,
    but a RECORD of which keys it read (and at what version) and which
    keys it intends to write. This read/write set is what Validate later
    checks for staleness."""
    write_set: dict[str, float]
    read_versions: dict[str, int]


def transfer_chaincode(state: WorldState, frm: str, to: str, amount: float) -> ExecutionResult:
    """Same business logic as v10/v11, now returning read/write sets
    instead of a whole new state dict."""
    if state.balances.get(frm, 0) < amount:
        raise ValueError(f"Insufficient funds: {frm} has {state.balances.get(frm, 0)}, needs {amount}")
    return ExecutionResult(
        write_set={
            frm: state.balances.get(frm, 0) - amount,
            to: state.balances.get(to, 0) + amount,
        },
        read_versions={frm: state.version_of(frm), to: state.version_of(to)},
    )

    peer_name: str
    result_hash: str

    name: str
    membership: MembershipService

    def endorse(
        self, chaincode: Callable, state: WorldState, *args

        if not self.membership.is_registered(self.name):

        concurrently, with no coordination between the clients who
        submitted them. Here: simple arrival order. Real systems use
        their own consensus algorithm for this -- the ordering nodes

        print(f"  [{self.name}] Received {len(proposals)} concurrently-proposed "
              f"transactions -- imposing a single order.")

class PermissionedBlockchain:
    def __init__(
        self, required_endorsers: set[str], min_endorsements: int, orderer_name: str
    ) -> None:
        self.required_endorsers = required_endorsers
        self.min_endorsements = min_endorsements
        self.orderer_name = orderer_name
        self.chain: list[Block] = [Block(0, "Genesis Block", "0" * 64, orderer_name)]
        self.state = WorldState()

    def validate_and_commit(self, tx: ProposedTransaction) -> bool:
        """VALIDATE step, now with TWO independent checks:
          (a) endorsement policy -- same as v10/v11
          (b) MVCC freshness -- did the state this tx's endorsement was
              computed against still hold true by the time it's actually
              being committed, or did an earlier transaction in this
              same ordered batch already change the same keys?
        """
        endorser_names = {e.peer_name for e in tx.endorsements}

        if not endorser_names.issuperset(self.required_endorsers):
            print(f"  REJECTED ({tx.description}): missing required endorsers "
                  f"{self.required_endorsers - endorser_names}")
            return False
        if len(tx.endorsements) < self.min_endorsements:
            print(f"  REJECTED ({tx.description}): not enough endorsements")
            return False
        if len({e.result_hash for e in tx.endorsements}) > 1:
            print(f"  REJECTED ({tx.description}): endorsers disagree on the result")
            return False

        # MVCC check: for every key this tx's endorsement read, is its
        # CURRENT version still what the endorsement assumed?
        for key, read_version in tx.execution_result.read_versions.items():
            current_version = self.state.version_of(key)
            if current_version != read_version:
                print(f"  REJECTED ({tx.description}): MVCC CONFLICT on '{key}' -- "
                      f"endorsed against version {read_version}, but current version "
                      f"is now {current_version} (changed by an earlier-ordered tx)")
                return False

        # Passed everything -- commit: apply the write set, bump versions,
        # and wrap it in a real hash-linked Block.
        for key, new_value in tx.execution_result.write_set.items():
            self.state.balances[key] = new_value
            self.state.versions[key] = self.state.version_of(key) + 1

        record = json.dumps(
            {"description": tx.description, "write_set": tx.execution_result.write_set},
            sort_keys=True,
        )
        previous_block = self.chain[-1]
        new_block = Block(len(self.chain), record, previous_block.hash, self.orderer_name)
        self.chain.append(new_block)

        print(f"  COMMITTED as Block #{new_block.index}: {tx.description}")
        return True

    automatically. On an MVCC conflict, don't give up: re-run EXECUTE
    against whatever the CURRENT state now is, and try again. This is

    Args:

        peers: Endorsing peers to use.
        chaincode: The smart contract function to run.
        chain: The ledger to submit to.
        orderer: The ordering service to sequence through.
        args: Arguments to pass to the chaincode.
        max_attempts: How many times to retry before giving up.

    Returns:
        True if eventually committed, False if all attempts were exhausted.

        ordered = orderer.order([tx])
        if chain.validate_and_commit(ordered[0]):
            return True
        print(f"    -> stale, retrying...\n")
    print(f"  Gave up after {max_attempts} attempts.")
    return False

Smart Contracts, Public-Chain Flavor

Same underlying idea as chaincode — deterministic code, independently re-run — but with no membership list to keep anyone out. That single difference forces two new problems into existence.

Ethereum, the EVM, and Ether — three different things

These get used interchangeably in conversation and that's exactly what makes them confusing.

Analogy

Ethereum is the country — the whole network of independent computers, launched 2015, agreeing on one shared history (it switched from Proof of Work to Proof of Stake in 2022, in an event called "The Merge" — everything built in Section 3 is how it actually runs today). The EVM (Ethereum Virtual Machine) is the factory every citizen has an identical copy of — the shared execution engine that runs smart contracts, guaranteeing every node gets the same result. Ether (ETH) is the currency you use to pay the factory for its work.

Ethereum vs EVM vs Ether
Ethereum
the country — thousands of independent nodes, one shared history
EVM
the factory — every citizen runs an identical copy
Ether
the currency — what you pay the factory with

Three nested things, one word problem. Nobody would confuse "France," "a French factory," and "euros" — crypto just forgot to give them three different names people actually use consistently.

Gas: measuring, not paying

Gas is a unit of measurement, not money. Ether is the money. Gas price is the exchange rate between them — usually quoted in gwei, a billionth of an ETH, the way fuel is priced in cents per litre, not fractions of a paycheck. Total fee = gas used × gas price. And gas limit is a hard spending cap you set upfront — the mechanism that stops a public, anyone-can-call network from being trivially destroyed by an accidental infinite loop or a deliberate spam attack. No membership list to ban the attacker with; instead, "prove you're willing to pay, upfront, proportional to exactly how much computation you're asking for." (For the record: gas does not, in fact, smell. It just costs money. Blockchain terminology remains undefeated at naming things in the most alarming way possible.)

"""
Blockchain 101 -- Toy Example #14: A toy EVM with gas metering.

Demonstrates the exact thing gas is FOR: a public network, with no
membership list to ban anyone, must still survive buggy or malicious
code. This toy virtual machine runs simple stack-based programs,
charges gas per instruction, and forcibly halts (with a full state
ROLLBACK) the instant gas runs out -- no matter how far through
execution it got.
"""

from __future__ import annotations

from dataclasses import dataclass, field


class OutOfGasError(Exception):
    """Raised when execution would need more gas than was authorized.
    In real Ethereum, this doesn't crash the network -- it just fails
    THIS ONE transaction, and the sender still pays for the gas burned
    up to the failure point. That's deliberate: even a failed attack
    costs the attacker real money."""


# Fixed, published cost per operation -- exactly like Ethereum's own gas
# schedule. Notice STORE costs far more than arithmetic: writing to
# permanent storage is genuinely expensive for every node to maintain
# forever, so it's priced accordingly (real Ethereum's SSTORE really is
# disproportionately costly compared to ADD/SUB for this exact reason).
GAS_COSTS: dict[str, int] = {
    "PUSH": 3,
    "POP": 2,
    "ADD": 3,
    "SUB": 3,
    "STORE": 20,
    "LOAD": 5,
    "JUMP": 8,
}


@dataclass
class ExecutionContext:
    """The scratch space for one contract call: a working stack, a view
    of storage, and a running gas tally."""
    storage: dict[str, int] = field(default_factory=dict)
    stack: list[int] = field(default_factory=list)
    gas_remaining: int = 0
    gas_used: int = 0


def execute(program: list[tuple], ctx: ExecutionContext) -> None:
    """Run a simple stack-based program, instruction by instruction,
    charging gas for each step. Mutates ctx in place. Raises
    OutOfGasError the instant gas_remaining can't cover the next
    instruction's cost -- execution stops EXACTLY there, not one
    instruction later.

    Args:
        program: A list of (opcode, *operands) tuples.
        ctx: The execution context to run against and mutate.
    """
    pc = 0
    while pc < len(program):
        opcode, *operand = program[pc]
        cost = GAS_COSTS[opcode]

        if ctx.gas_remaining < cost:
            raise OutOfGasError(
                f"Out of gas at instruction #{pc} ({opcode}): "
                f"needed {cost}, had {ctx.gas_remaining} remaining"
            )
        ctx.gas_remaining -= cost
        ctx.gas_used += cost

        if opcode == "PUSH":
            ctx.stack.append(operand[0])
        elif opcode == "POP":
            ctx.stack.pop()
        elif opcode == "ADD":
            b, a = ctx.stack.pop(), ctx.stack.pop()
            ctx.stack.append(a + b)
        elif opcode == "SUB":
            b, a = ctx.stack.pop(), ctx.stack.pop()
            ctx.stack.append(a - b)
        elif opcode == "STORE":
            key = operand[0]
            ctx.storage[key] = ctx.stack.pop()
        elif opcode == "LOAD":
            key = operand[0]
            ctx.stack.append(ctx.storage.get(key, 0))
        elif opcode == "JUMP":
            pc = operand[0]
            continue

        pc += 1

    """Run a contract call in an ISOLATED sandbox. State changes only

    database transaction, and exactly like our very first Blockchain's
    all-or-nothing tamper-evidence, just applied to execution instead
    of hashing.

    Args:
        program: The instructions to run.
        gas_limit: Maximum gas authorized for this call.
        persistent_storage: The REAL, shared contract storage. Only
            touched if execution succeeds completely.

    Returns:
        (success, gas actually used, human-readable outcome message)
    """
    sandbox = dict(persistent_storage)  # execute against a throwaway copy
    ctx = ExecutionContext(storage=sandbox, gas_remaining=gas_limit)
    try:
        execute(program, ctx)
    except OutOfGasError as e:
        # ROLLBACK: persistent_storage is untouched. Gas is still "spent"
        # in reality (the attacker/bug author still pays), even though
        # nothing they attempted actually took effect.
        return False, ctx.gas_used, str(e)

    persistent_storage.clear()
    persistent_storage.update(ctx.storage)  # COMMIT
    return True, ctx.gas_used, "Success"

The oracle problem

Every contract in this document only ever reads and writes its own storage — zero ability to reach outside itself. Not an oversight: if a contract could freely query an external website, two nodes running the exact same contract at slightly different moments could get different answers, and "everyone independently recomputes and must agree" collapses instantly. A closed universe is the price of trustless determinism.

But real contracts need real-world facts — crop insurance needs to know if it rained, a lending protocol needs today's ETH price. An oracle bridges that gap by submitting real-world data on-chain as an ordinary transaction. The actual problem: everything this whole document has built protects what happens inside the chain. An oracle is a single bridge FROM the untrustworthy outside world INTO it. If the oracle lies or gets manipulated, the contract will faithfully, "correctly" execute on top of a lie.

"""
Blockchain 101 -- Toy Example #15: The Oracle Problem.

Compares a NAIVE smart contract trusting a single price oracle against
a ROBUST one requiring multiple independent oracles + median -- then
shows the robust version's actual limit: it can't detect a lie that
every honest oracle unknowingly agrees on.
"""

from __future__ import annotations
from dataclasses import dataclass


@dataclass
class Oracle:
    """An independent, named source reporting a real-world price."""
    name: str
    reported_price: float


def naive_liquidation_check(
    collateral_eth: float, debt_usd: float, oracle: Oracle, threshold: float = 1.5
) -> bool:
    """Trusts ONE oracle. If it lies, the contract faithfully acts on the lie."""
    ratio = (collateral_eth * oracle.reported_price) / debt_usd
    return ratio < threshold  # True = liquidate


def robust_liquidation_check(
    collateral_eth: float, debt_usd: float, oracles: list[Oracle], threshold: float = 1.5
) -> bool:
    """Requires MULTIPLE independent oracles, uses the MEDIAN -- the same
    'many independent parties must agree' principle as PoW verification,
    PoS endorsement, and Fabric's endorsement policy, aimed at price
    data instead of transaction integrity."""
    prices = sorted(o.reported_price for o in oracles)
    median_price = prices[len(prices) // 2]
    ratio = (collateral_eth * median_price) / debt_usd
    return ratio < threshold


if __name__ == "__main__":
    collateral_eth, debt_usd = 10.0, 12000.0
    print(f"=== Loan: {collateral_eth} ETH collateral against ${debt_usd:,.0f} debt ===")
    print(f"  At real ETH price $2,000: ratio = {(collateral_eth*2000)/debt_usd:.2f} "
          f"(threshold is 1.5 -- this is genuinely healthy)\n")

    honest = [Oracle("Coinbase-Feed", 2000.0), Oracle("Kraken-Feed", 1990.0), Oracle("Binance-Feed", 2010.0)]
    manipulated = Oracle("Thin-DEX-Feed", 500.0)  # one exchange's price got attacked

    print("=== Naive contract: trusts ONLY the manipulated feed ===")
    print(f"  Liquidated? {naive_liquidation_check(collateral_eth, debt_usd, manipulated)}"
          f"  <- WRONG, attacker just stole this collateral\n")

    print("=== Robust contract: median of several independent oracles ===")
    all_oracles = honest + [manipulated]
    prices = sorted(o.reported_price for o in all_oracles)
    print(f"  Prices seen: {prices} | median: {prices[len(prices)//2]}")
    print(f"  Liquidated? {robust_liquidation_check(collateral_eth, debt_usd, all_oracles)}"
          f"  <- CORRECT, one bad feed couldn't move the median\n")

    print("=== But if the REAL market crashes (all oracles honestly agree) ===")
    crashed = [Oracle("Coinbase-Feed", 600.0), Oracle("Kraken-Feed", 580.0), Oracle("Binance-Feed", 590.0)]
    print(f"  Prices seen: {sorted(o.reported_price for o in crashed)}")
    print(f"  Liquidated? {robust_liquidation_check(collateral_eth, debt_usd, crashed)}"
          f"  <- Still triggers. Honest agreement is no defense if reality itself was manipulated first.")

Bullshit Detector

Requiring multiple independent oracles and taking the median — the same "many independent parties must agree" principle as PoW verification, PoS endorsement, and Fabric's endorsement policy — genuinely stops a single corrupted feed from lying successfully. It does not stop a real DeFi attack pattern: manipulate the actual underlying market on a thinly-traded exchange first, so every honest oracle faithfully reports the same manipulated number. The failure isn't dishonest oracles. It's honest oracles reporting a lie they had no way to detect.

Key Takeaway
Public smart contracts trade the permissioned world's "known participants" for two new defenses: gas (make computation cost real money, so anonymous spam is survivable) and oracles-with-redundancy (make external data trustworthy by requiring independent agreement) — neither of which a permissioned chain needed to invent in the first place.

The Scalability Trilemma, and What Part 2 Covers

Every design decision in this document has secretly been trading off between three things that fight each other: decentralization (how many independent people can participate), security (how expensive is an attack), and scalability (transactions per second). The common claim: pick two.

The Scalability Trilemma

Bitcoin and Ethereum camp out near the Decentralization-Security edge, paying for it in throughput. Mastercard's MTN camps out near Security-Scalability, paying for it in "sorry, who are you again?"

Your own instinct, and the honest pushback

i feel like the security and scalability is the most important. decentralization causes the other two to topple hahahaha.On the trilemma, mid-conversation

That instinct already matches something real — it's the exact strategic thesis behind Mastercard's MTN (Section 4): known validators instead of anonymous strangers, controlled membership instead of "anyone can join." Sacrificing decentralization genuinely buys real security and scalability.

Bullshit Detector

The honest counter-argument, from people who take decentralization seriously: cryptographic tamper-evidence survives perfectly fine on a permissioned chain — nobody disputes that. What decentralization specifically buys is censorship resistance — no single government, company, or coalition can unilaterally freeze your funds or block your participation. Give that up, and you've reintroduced exactly that risk, just now wearing blockchain technology instead of a plain database. Whether that matters is entirely about your threat model: worried about hackers and fraud, permissioned wins easily. Worried about the institution itself being the threat, no amount of security or scalability substitutes for decentralization.

One honest footnote: "trilemma" isn't a proven mathematical law the way double-spend or preimage-resistance are — it's a widely-observed engineering tension, popularised by Ethereum's Vitalik Buterin, not a formal impossibility theorem. Layer 2s (rollups, sidechains) exist specifically to try to cheat it — Part 2 territory.

DeFi ≠ crypto

Crypto broadly is anything running on a blockchain. DeFi (Decentralized Finance) is specifically financial services — lending, borrowing, trading — run by smart contracts instead of a company in the middle. Coinbase is centralized crypto (trust their staff, same as a bank). Uniswap or Aave are DeFi — a smart contract executes automatically based purely on the math, nobody's permission needed. Which also means nobody's around to hit undo when the math does exactly what you told it to and you didn't mean it.

Election voting: the honest skeptical take

One of the most popularly proposed blockchain applications, and one of the ones actual cryptographers are most skeptical of. Blockchain solves "was this recorded vote tampered with after casting" — real value. The actual hard problems live elsewhere: voter coercion (provably proving how you voted lets someone force you to prove it — anti-coercion requires being able to convincingly lie about your own vote, which fights directly against blockchain's whole "everything is provably true" nature), and endpoint security (malware on your own device can alter your vote before it's ever signed — no ledger technology downstream fixes a lie that already happened upstream). Genuinely interesting for narrow uses like auditable tallying; deeply unconvincing as a full remote-voting replacement.

From the Lab

Carbon credits — the favourite, and for good reason. The market has historically been plagued by double-counting: the same emissions reduction sold to two buyers, or a "retired" credit quietly reused elsewhere. That's the double-spend problem from Section 1, wearing an environmental-policy costume. A public, tamper-evident, Merkle-provable ledger is a near-perfect structural fit for "prove this credit was only ever claimed once, by exactly one party, forever."

Coming in Part 2

Deliberately moving past finance, because finance applications tend to bury the concepts under complexity that obscures rather than reveals them. External applications teach blockchain better: OpenCerts and TradeTrust in proper depth, carbon credit registries, supply chain provenance, and the honest verdict on where blockchain earns its keep versus where it's expensive marketing theater wrapped around a problem a normal database already solved.

Bullshit Detector

The sharpest single test for any "blockchain for X" pitch, corporate or otherwise: who are the mutually distrusting parties here, and why can't one of them just be trusted to keep the ledger? If already trusting one company's internal system, bolting blockchain onto it buys marketing sparkle, not function — a normal database with decent access logs does the job faster and cheaper. If there's a clean answer to "who doesn't trust whom," blockchain might genuinely be earning its keep.

Confusion Busters & Glossary

Every term used across this document, in one place, for the "wait, what did that mean again" moments. No judgment. Even the people who invented half of these terms Google them sometimes.

Block
A hash-linked container holding data (often a Merkle root) plus the previous block's hash. The atomic unit consensus agrees on.
Hash / SHA-256
A deterministic, one-way fingerprint of any input. Same input always gives the same output; the reverse direction is computationally infeasible.
Avalanche effect
Changing an input by one character produces a completely unrelated hash output. No partial credit, no gradient to climb.
Preimage resistance
The formal name for “can't work backwards from a hash to its input.” The actual reason you can't fake a hash by editing it.
Nonce
A number a miner is free to change and re-hash with, hunting for an output that satisfies the difficulty target.
Genesis block
The first block in a chain, with no parent — conventionally points to a previous_hash of all zeros.
Merkle root
One hash summarizing an entire batch of documents, built bottom-up by repeatedly hashing pairs. The only thing that needs to go on-chain.
Merkle proof
The minimal set of sibling hashes (log₂ N of them) needed to prove one item belongs to a batch, without needing the other N-1 items.
Double-spend problem
The specific disaster in currency systems if two conflicting spends of the same funds both get accepted — the reason consensus exists at all.
Byzantine Generals Problem
The general version of double-spend: how untrusting strangers agree on one shared truth with no referee and some possibly-lying participants.
Proof of Work (PoW)
Consensus via computational lottery — miners burn electricity guessing nonces; cheating means wasting real resources for nothing.
Proof of Stake (PoS)
Consensus via staked capital — validators lock up money as collateral; cheating means the protocol destroys it.
Mining
The brute-force search for a nonce whose resulting hash satisfies a difficulty target.
Staking
Locking up currency as collateral to become eligible for weighted-random selection as a block proposer.
Slashing
The protocol algorithmically destroying some or all of a validator's stake after provable misbehaviour.
Equivocation
Signing two conflicting blocks for the same height — unambiguous, provable misbehaviour, regardless of intent.
51% attack
Acquiring enough hashing power (PoW) or stake (PoS) to rewrite recent history — theoretically possible, deliberately made astronomically expensive.
Permissionless / Public chain
Anyone can read, transact, and become a validator, with no identity check. Bitcoin, Ethereum.
Permissioned / Private chain
Only known, vetted organizations may participate. Hyperledger Fabric, R3 Corda, Mastercard's MTN.
Membership Service
The registry of known, vetted identities that gates participation on a permissioned chain — has no equivalent on a public chain.
Chaincode
Hyperledger Fabric's term for a smart contract — deterministic business logic every endorsing peer independently runs.
Execute-Order-Validate
Fabric's consensus shape: endorsing peers run chaincode locally, an ordering service sequences the results, then peers validate before committing.
Endorsement
A peer's signed claim of what result they got from running chaincode — not yet committed to the ledger.
Ordering service
A separate service (often Raft-based) whose only job is imposing one sequence on concurrently-submitted, already-endorsed transactions.
MVCC (multi-version concurrency control)
The check at commit time: was the state a transaction's endorsement assumed still current, or did an earlier-ordered transaction already change it?
Smart contract
Deterministic code stored on a blockchain, whose execution every node independently re-runs and must agree on.
Ethereum
The public, general-purpose blockchain network (switched from PoW to PoS in 2022's “The Merge”) that runs the EVM.
EVM (Ethereum Virtual Machine)
The shared execution engine every Ethereum node runs an identical copy of, guaranteeing consistent smart-contract results.
Ether (ETH)
Ethereum's native currency — a tradeable asset that also pays for gas.
Gas
The unit measuring how much computational work an operation costs — not money itself.
Gas price / gwei
How much ETH you're willing to pay per unit of gas, typically quoted in gwei (one billionth of an ETH).
Gas limit
The maximum gas authorized for a transaction — a hard spending cap that halts runaway or malicious code.
Oracle
A service that submits real-world data on-chain as an ordinary transaction, since contracts otherwise cannot see outside their own storage.
DeFi (Decentralized Finance)
Financial services — lending, trading, borrowing — run by smart contracts instead of a company in the middle.
Full node
A computer storing and independently re-verifying the entire blockchain history from genesis.
Pruned node
A node that verified everything as it arrived, then discarded old raw data, keeping only headers and current state.
Light client
A lightweight participant that trusts a third party's full node rather than independently verifying everything itself.
Scalability Trilemma
The widely-observed (not formally proven) tension between decentralization, security, and scalability — popularised by Vitalik Buterin.
